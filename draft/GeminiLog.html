Hoàn toàn có thể xây dựng một web app giúp trẻ em học lập trình. Mô hình này rất phổ biến và đã có nhiều nền tảng thành công như Code.org, SoloLearn hay Scratch. [1, 2, 3, 4]
Để xây dựng một web app như vậy, bạn có thể tham khảo cấu trúc và các bước cốt lõi sau:
1. Lựa chọn ngôn ngữ và công nghệ phù hợp với độ tuổi
  • Trẻ nhỏ (6 - 10 tuổi): Nên tích hợp giao diện kéo thả dạng khối lệnh (Blockly / Scratch) để làm quen với tư duy logic mà không bị nản vì lỗi cú pháp. [1]
  • Trẻ lớn hơn (12 tuổi trở lên): Có thể tích hợp các ngôn ngữ hiện đại và thực tế như:
    • Python: Phù hợp bắt đầu với lập trình văn bản nhờ cú pháp ngắn gọn, dễ đọc.
    • JavaScript / HTML / CSS: Giúp trẻ tạo ra các trang web hoặc trò chơi tương tác nhìn thấy được kết quả ngay lập tức trên trình duyệt. [1, 2, 3]
2. Các thành phần chính cần có trong Web App
  • Trình biên tập mã trực tuyến (Online Code Editor): Tích hợp các thư viện như Monaco Editor (của VS Code) hoặc CodeMirror để trẻ viết code trực tiếp trên web.
  • Hệ thống thực thi an toàn (Sandbox / Compiler Backend): Chạy code của trẻ trong môi trường biệt lập (sử dụng Docker hoặc các API dịch vụ biên dịch mã nguồn) để tránh bị lỗi bảo mật hoặc treo hệ thống.
  • Giao diện trực quan & Gamification (Biến việc học thành trò chơi):
    • Hệ thống nhân vật, huy hiệu (Badge), bảng xếp hạng, hoặc làm nhiệm vụ vượt qua các màn chơi (giống Code.org).
    • Khung hiển thị kết quả ngay cạnh khung viết code (cho ra hình vẽ, nhân vật di chuyển, hoặc trang web mini). [1, 2]
  • Trợ lý hoặc phản hồi bằng AI (Tùy chọn): Gợi ý lỗi sai và giải thích bằng ngôn ngữ thân thiện với trẻ khi code bị lỗi thay vì chỉ hiện dòng thông báo lỗi (Error Stack) khô khan.
3. Công nghệ gợi ý để phát triển Web App
  • Frontend: React.js, Vue.js, hoặc Next.js kết hợp Tailwind CSS để tạo giao diện sinh động, dễ thương, dễ thao tác cho trẻ.
  • Backend: Node.js, Python (FastAPI/Django) hoặc dùng các nền tảng Backend-as-a-Service (Firebase, Supabase) để quản lý tài khoản, tiến độ học tập và bài tập của trẻ.
Nếu bạn muốn bắt đầu, bạn có thể cho tôi biết:
  • Đối tượng trẻ em bạn hướng tới ở độ tuổi nào (ví dụ: tiểu học hay cấp 2)?
  • Bạn muốn tập trung vào dạng kéo thả hay viết code thực tế ngay từ đầu?

Tôi có thể gợi ý chi tiết hơn về kiến trúc kỹ thuật hoặc lộ trình tính năng cho bạn.

 

Ý tưởng phát triển một web app giúp trẻ học lập trình thông qua robot giả lập (Robot Simulator) là một hướng đi xuất sắc. Nó kết hợp được tư duy logic của lập trình với sự trực quan, sinh động của thế giới vật lý, giúp trẻ không bị nhàm chán như khi học code xuất dữ liệu text thông thường.
Để hiện thực hóa ý tưởng này trên nền tảng web, bạn cần giải quyết bài toán cốt lõi: Kết nối giữa Khung nhập code (Code Editor) và Khung môi trường 3D/2D (Simulator Environment).
Dưới đây là kiến trúc và giải pháp công nghệ tối ưu để xây dựng web app này:
1. Mô hình hoạt động của ứng dụng (Workflow)
  1. Trẻ viết code: Trẻ kéo thả khối lệnh hoặc viết code bằng ngôn ngữ hiện đại (ví dụ: Python/JavaScript).
  2. Biên dịch & Chuyển đổi: Hệ thống dịch các câu lệnh đó thành các lệnh điều khiển robot tương ứng (ví dụ: move_forward(5), turn_left()).
  3. Thực thi giả lập: Môi trường giả lập nhận lệnh, tính toán vật lý (va chạm, tốc độ, ma sát) và hiển thị chuyển động của robot theo thời gian thực.
  4. Phản hồi: Trẻ nhìn thấy robot chạy trên màn hình (vượt chướng ngại vật, đi trong mê cung) và biết mình code đúng hay sai.
2. Các công nghệ cốt lõi nên sử dụng
Để chạy mượt mà ngay trên trình duyệt web mà không bắt người dùng cài đặt phần mềm, bạn nên tận dụng các thư viện JavaScript mạnh mẽ sau:
Khung Giả lập (Simulator Engine)
  • Nếu làm Đồ họa 3D (Được khuyến khích vì tạo cảm giác chân thực):
    • Three.js / React Three Fiber: Thư viện đồ họa 3D phổ biến nhất trên web để dựng mô hình robot, bánh xe, cảm biến và môi trường xung quanh.
    • Cannon.js / Ammo.js: Bộ xử lý vật lý (Physics Engine) đi kèm để tính toán việc robot va chạm tường, trọng lực, hoặc quán tính khi phanh.
  • Nếu làm Đồ họa 2D (Nhẹ hơn, dễ phát triển hơn):
    • Matter.js hoặc PixiJS: Rất phù hợp nếu bạn muốn làm robot dạng góc nhìn từ trên xuống (Top-down view) di chuyển trong mê cung 2D.
Khung Viết code (Code Editor & Compiler)
  • Dạng kéo thả (Dành cho trẻ nhỏ hoặc bước làm quen):
    • Google Blockly / Scratch Blocks: Bạn có thể tùy biến các khối lệnh riêng cho robot (Ví dụ khối: "Đi thẳng [ ] bước", "Nếu [Gặp tường] thì [Rẽ trái]"). Blockly có sẵn tính năng tự động chuyển đổi các khối này thành code Python hoặc JavaScript sạch.
  • Dạng viết code văn bản (Dành cho trẻ lớn hơn):
    • Pyodide hoặc Brython: Giúp chạy trực tiếp code Python ngay trên trình duyệt của trẻ mà bạn không cần thuê server Backend đắt đỏ để biên dịch. Nó cho phép code Python tương tác trực tiếp với giao diện 3D (JavaScript) của Web App.

Bạn nên bắt đầu từ những bước nhỏ để kiểm tra tính khả thi trước khi làm một hệ thống quá phức tạp:

  • Bạn muốn hướng tới giả lập 3D (giống các game như Roblox) hay giả lập 2D cho đơn giản và mượt mà trên máy cấu hình yếu?
  • Bạn có muốn tích hợp các mô hình robot có thật ngoài đời (như Lego Mindstorms, Arduino Car) để sau này trẻ có thể nạp code từ web vào robot thật không?

 

Lựa chọn giả lập 2D là một hướng đi cực kỳ thông minh cho giai đoạn đầu. Nó vừa giúp web app chạy mượt mà trên các máy tính cấu hình yếu của trường học (như Chromebook, máy tính bảng), vừa giúp trẻ dễ dàng làm quen với tư duy thuật toán mà không bị rối mắt bởi không gian 3D.
Để mô phỏng các loại robot có thật ngoài đời như Arduino Car (xe 2 bánh độc lập - Differential Drive), robot lau nhà, hay robot đá bóng, bạn cần xây dựng hệ thống dựa trên các nền tảng kỹ thuật và cấu trúc logic sau:
1. Kiến trúc kỹ thuật khuyến nghị cho Web App 2D
Bạn có thể xây dựng toàn bộ logic này chạy trực tiếp trên trình duyệt (Client-side) để tối ưu chi phí server và tăng tốc độ phản hồi:
  • Engine Vật lý & Hiển thị 2D: Matter.js (tốt nhất cho mô phỏng vật lý) kết hợp với PixiJS (để vẽ đồ họa mượt mà). Matter.js sẽ giúp bạn tính toán các va chạm của robot đá bóng với quả bóng, hoặc lực ma sát của bánh xe Arduino.
  • Khung lập trình (Code Editor): Google Blockly để trẻ xếp hình khối lệnh, cấu hình để nó xuất ra mã JavaScript/Python.
  • Cầu nối Thực thi (Execution Bridge): Sử dụng cơ chế vòng lặp requestAnimationFrame của JavaScript. Mỗi khung hình (frame), hệ thống sẽ đọc lệnh từ code của trẻ (ví dụ: robot.setSpeed(100, 50)) và cập nhật vận tốc vào các bánh xe giả lập trong Matter.js.
2. Mô phỏng các cơ chế vật lý thực tế từ Arduino Car
Để giả lập giống với robot thật ngoài đời (như các bộ Kit xe Arduino Uno R3 thông dụng), bạn cần lập trình các hàm toán học mô phỏng lại các linh kiện vật lý sau:
A. Hệ thống chuyển động (Kinematics)
Arduino Car thường dùng cơ chế Differential Drive (2 bánh chủ động phía sau, 1 bánh xe đa hướng/bánh bướm phía trước):
  • Đi thẳng: Tốc độ bánh trái = Tốc độ bánh phải.
  • Xoay tại chỗ: Tốc độ bánh trái = - Tốc độ bánh phải.
  • Cua vòng: Tốc độ hai bánh lệch nhau (Bánh nào quay chậm hơn thì xe cua về phía đó).
  • Trong code giả lập: Bạn sẽ dùng thuật toán toán học để chuyển đổi từ tốc độ 2 bánh xe thành hướng di chuyển (X, Y) và góc quay (Angle θ) của robot trên màn hình.
B. Giả lập các loại Cảm biến (Sensors) phổ biến
Đây là phần thú vị nhất giúp trẻ học được tư duy lập trình điều khiển (Control Theory):
Cảm biến ngoài đời Cách giả lập trong Web App 2D Ứng dụng trong bài học cho trẻ
Cảm biến siêu âm (Ultrasonic HC-SR04) Bắn các tia (Raycasting) từ đầu robot ra phía trước, tính khoảng cách đến vật cản gần nhất. Robot lau nhà: Né chướng ngại vật, né chân bàn ghế.
Cảm biến dò đường (Line IR Sensor) Kiểm tra màu sắc của điểm ảnh (Pixel) tại vị trí đặt mắt đọc (thường là 2-3 điểm dưới gầm robot). Arduino Car: Lập trình cho xe chạy men theo vạch màu đen trên sàn.
Cảm biến va chạm (Bumper Switch) Dùng tính năng Check Collision của Matter.js khi thân robot chạm vào tường/quả bóng. Robot đá bóng / Lau nhà: Quay đầu lại hoặc đẩy bóng khi va chạm.
3. Gợi ý thiết kế các "Màn chơi" (Sân chơi giả lập) cho trẻ
Bạn có thể chia Web App thành các chế độ hoặc phòng Lab khác nhau dựa trên các loại robot bạn đã nêu:
  • Phòng Lab Robot Lau Nhà (Diện tích / Bao phủ):
    • Bối cảnh: Một căn phòng 2D ngẫu nhiên có bàn, ghế, sofa.
    • Nhiệm vụ: Trẻ phải lập trình thuật toán (ví dụ: thuật toán di chuyển ngẫu nhiên ziczac hoặc bám tường) để robot đi qua được nhiều diện tích sàn nhất trong vòng 2 phút. Sàn nhà robot đi qua sẽ đổi màu (thể hiện đã lau sạch).
  • Phòng Lab Robot Đá Bóng (Vật lý / Đối kháng):
    • Bối cảnh: Sân bóng mini 2D, có khung thành và 1 quả bóng có vật lý (bo tròn, có độ nảy, có ma sát lăn).
    • Nhiệm vụ: Lập trình cho robot dò tìm vị trí quả bóng (dựa trên khoảng cách và góc độ), tiếp cận, đẩy bóng vào lưới đối phương. Có thể nâng cấp thành màn chơi 2 robot (mình đấu với AI lập trình sẵn).
4. Khả năng mở rộng: Từ Giả lập bước ra Đời thật
Vì bạn muốn dựa trên các mô hình có thật như Arduino Car, bạn hoàn toàn có thể thiết kế hệ thống khối lệnh Blockly dịch thẳng ra code C++ (Arduino Web Editor).
  1. Trẻ thử nghiệm, sửa lỗi (Debug) trên web app giả lập 2D cho đến khi robot chạy hoàn hảo.
  2. Trẻ bấm nút "Xuất code Arduino", hệ thống sẽ cho tải về file .ino hoặc nạp thẳng vào mạch Arduino thật qua cổng USB (sử dụng công nghệ Web Serial API trực tiếp từ trình duyệt Chrome).
  3. Robot thật ngoài đời sẽ chạy y hệt như những gì trẻ đã thấy trên màn hình giả lập. Đây sẽ là một điểm cộng (Unique Selling Point) cực lớn cho sản phẩm của bạn.

Để bắt đầu xây dựng một bản thử nghiệm (Prototype) nhỏ, bạn có muốn tôi hỗ trợ phác thảo cấu trúc dữ liệu của một con Robot (vị trí, góc quay, hàm di chuyển) bằng JavaScript hoặc cấu trúc một bài học mẫu không?

 

Dưới đây là phác thảo chi tiết cho cả hai phần: Cấu trúc dữ liệu mã nguồn JavaScript điều khiển robot 2 bánh độc lập (Differential Drive) và Cấu trúc một bài học mẫu theo mô hình Gamification (học qua trò chơi) để bạn dễ dàng triển khai.
PHẦN 1: Cấu trúc dữ liệu & Logic Robot (JavaScript)
Đây là mô hình toán học mô phỏng một chiếc Arduino Car 2 bánh. Hệ thống giả lập (như Matter.js hoặc vòng lặp requestAnimationFrame) sẽ gọi hàm update() liên tục sau mỗi khung hình để cập nhật vị trí mới dựa trên vận tốc của hai bánh xe.
javascript
class ArduinoCar2D {
    constructor(x, y, angle = 0) {
        // --- 1. Trạng thái vật lý ---
        this.x = x;               // Tọa độ X trên màn hình (pixels)
        this.y = y;               // Tọa độ Y trên màn hình (pixels)
        this.angle = angle;       // Góc quay của robot (tính bằng Radian, 0 là hướng sang phải)
        this.radius = 25;         // Kích thước thân xe (bán kính vòng tròn bao phủ)
        this.wheelBase = 40;      // Khoảng cách giữa 2 bánh xe (độ rộng trục xe)

        // --- 2. Bộ điều khiển Động cơ (Lệnh từ Code của trẻ) ---
        this.leftWheelSpeed = 0;  // Vận tốc bánh trái (-100 đến 100)
        this.rightWheelSpeed = 0; // Vận tốc bánh phải (-100 đến 100)
        this.maxSpeed = 4;        // Giới hạn tốc độ di chuyển tối đa trong giả lập

        // --- 3. Dữ liệu Cảm biến (Đọc đầu vào môi trường) ---
        this.sensors = {
            ultrasonicDistance: 999, // Khoảng cách tới vật cản trước mặt (cm/pixels)
            lineSensors: [0, 1, 0]   // Trạng thái 3 mắt đọc dưới gầm xe: [Trái, Giữa, Phải] (0: Trắng, 1: Đen)
        };
    }

    /**
     * Hàm nhận lệnh điều khiển động cơ từ code của trẻ (tương tự hàm trong Arduino)
     */
    setMotors(leftSpeed, rightSpeed) {
        // Giới hạn giá trị truyền vào từ -100% đến 100%
        const clamp = (val) => Math.max(-100, Math.min(100, val));
        
        // Quy đổi phần trăm tốc độ ra vận tốc thực tế trong game
        this.leftWheelSpeed = (clamp(leftSpeed) / 100) * this.maxSpeed;
        this.rightWheelSpeed = (clamp(rightSpeed) / 100) * this.maxSpeed;
    }

    /**
     * Hàm cập nhật vị trí vật lý (Được gọi liên tục trong vòng lặp Game Loop)
     * Áp dụng thuật toán Differential Drive Kinematics
     */
    update(deltaTime) {
        // Tốc độ trung bình tiến lên của robot
        const linearVelocity = (this.leftWheelSpeed + this.rightWheelSpeed) / 2;
        
        // Tốc độ góc (vận tốc xoay hướng của robot)
        const angularVelocity = (this.rightWheelSpeed - this.leftWheelSpeed) / this.wheelBase;

        // 1. Cập nhật góc quay mới
        this.angle += angularVelocity * deltaTime;

        // 2. Cập nhật tọa độ X, Y mới dựa trên hướng (angle) hiện tại
        this.x += linearVelocity * Math.cos(this.angle) * deltaTime;
        this.y += linearVelocity * Math.sin(this.angle) * deltaTime;
    }

    /**
     * Hàm cập nhật dữ liệu cảm biến (Nhận thông tin từ môi trường map)
     */
    updateSensors(environmentData) {
        // Giả lập bắn tia (Raycasting) để tính toán khoảng cách vật cản
        this.sensors.ultrasonicDistance = this.calculateRaycast(environmentData);
        
        // Giả lập đọc màu sàn tại vị trí 3 mắt đọc dưới gầm
        this.sensors.lineSensors = this.readFloorPixels(environmentData);
    }
}
Use code with caution.

Bạn thấy cấu trúc này đã phù hợp với định hướng của mình chưa? Nếu muốn đi sâu vào lập trình, tôi có thể viết tiếp cho bạn phần thuật toán toán học xử lý bắn tia (Raycasting) để giả lập cảm biến siêu âm hoặc giao diện UI kéo thả nên bố trí thế nào.

 

Để giả lập cảm biến siêu âm (như con HC-SR04 trên xe Arduino) trong môi trường 2D, thuật toán Raycasting (Bắn tia) là giải pháp tối ưu nhất.
Về bản chất, chúng ta sẽ phóng một tia thẳng từ tâm robot ra phía trước theo hướng xe đang nhìn. Tia này sẽ tăng dần độ dài cho đến khi nó chạm vào một cạnh của vật cản (tường, chướng ngại vật). Khoảng cách từ robot đến điểm va chạm đó chính là giá trị cảm biến siêu âm đọc được.
Dưới đây là công thức toán học và đoạn mã JavaScript chi tiết để bạn tích hợp vào Web App của mình.
1. Thuật toán toán học: Giao điểm giữa Tia và Đoạn thẳng (Ray-Line Intersection)
Môi trường 2D của bạn sẽ gồm các chướng ngại vật được cấu tạo từ các đoạn thẳng (Line segments). Mỗi đoạn thẳng nối từ điểm A(x₁, y₁) đến B(x₂, y₂).Tia cảm biến phát ra từ Robot tại tâm \(P(x_p, y_p)\) và hướng theo một góc θ (góc của robot).
Để tìm giao điểm, ta sử dụng công thức định thức toán học để kiểm tra xem tia có cắt đoạn thẳng AB hay không:
Trong đó \(Q(x_q, y_q)\) là một điểm nằm rất xa trên hướng bắn của tia (\(x_q = x_p + \cos(\theta) \times \text{maxDist}\)).
  • Điều kiện cắt nhau: Nếu 0 ≤ t ≤ 1 và u ≥ 0, tia đã cắt đoạn thẳng AB. Điểm cắt sẽ có khoảng cách tới robot là u × maxDist.
2. Triển khai bằng JavaScript
Dưới đây là hàm tính toán khoảng cách cảm biến. Bạn truyền vào tọa độ, góc quay của robot và danh sách tất cả các bức tường/chướng ngại vật trong bản đồ.
javascript
/**
 * Hàm tính khoảng cách từ robot đến vật cản gần nhất (Giả lập cảm biến siêu âm)
 * @param {Object} robot - Đối tượng robot (x, y, angle)
 * @param {Array} walls - Danh sách các bức tường, mỗi tường dạng {x1, y1, x2, y2}
 * @param {number} maxRange - Tầm xa tối đa của cảm biến siêu âm (ví dụ: 300 pixels)
 * @returns {number} Khoảng cách ngắn nhất tìm được (nếu không thấy trả về maxRange)
 */
function getUltrasonicDistance(robot, walls, maxRange = 300) {
    let minDistance = maxRange;

    // 1. Xác định điểm xuất phát của tia (tâm robot) và hướng bắn tia
    const x_p = robot.x;
    const y_p = robot.y;
    
    // Điểm ảo Q nằm ở cuối tầm xa của cảm biến theo hướng góc của robot
    const x_q = x_p + Math.cos(robot.angle) * maxRange;
    const y_q = y_p + Math.sin(robot.angle) * maxRange;

    // 2. Duyệt qua từng đoạn thẳng (bức tường) trong môi trường để tìm giao điểm
    for (let wall of walls) {
        const x1 = wall.x1;
        const y1 = wall.y1;
        const x2 = wall.x2;
        const y2 = wall.y2;

        // Tính mẫu số (Denominator)
        const den = (x1 - x2) * (y_p - y_q) - (y1 - y2) * (x_p - x_q);
        
        // Nếu mẫu số bằng 0, tia và tường song song với nhau -> Không cắt
        if (den === 0) continue;

        // Tính các hệ số t và u theo công thức định thức
        const t = ((x1 - x_p) * (y_p - y_q) - (y1 - y_p) * (x_p - x_q)) / den;
        const u = -((x1 - x2) * (y1 - y_p) - (y1 - y2) * (x1 - x_p)) / den;

        // Kiểm tra xem giao điểm có nằm trong đoạn thẳng của bức tường và trên tia bắn ra không
        if (t >= 0 && t <= 1 && u >= 0 && u <= 1) {
            // Tính tọa độ điểm va chạm thực tế
            const intersectX = x1 + t * (x2 - x1);
            const intersectY = y1 + t * (y2 - y1);

            // Tính khoảng cách từ tâm robot đến điểm va chạm (Công thức Pitago)
            const dist = Math.sqrt(Math.pow(intersectX - x_p, 2) + Math.pow(intersectY - y_p, 2));

            // Cập nhật khoảng cách nhỏ nhất (vật cản gần nhất)
            if (dist < minDistance) {
                minDistance = dist;
            }
        }
    }

    // Trừ đi bán kính của robot nếu bạn muốn tính khoảng cách từ "đầu xe" thay vì từ "tâm xe"
    const finalDistance = minDistance - (robot.radius || 0);
    return Math.max(0, finalDistance); 
}
Use code with caution.

Để hoàn thiện logic điều khiển xe, bạn có cần tôi hỗ trợ viết tiếp thuật toán quét pixel để làm cảm biến dò đường (Line Sensor - đi theo vạch đen) không, hay bạn muốn chuyển sang thiết kế giao diện kéo thả khối lệnh?

Để làm Cảm biến dò đường (Line Follower Sensor) cho robot giả lập 2D (như các thanh cảm biến 3 mắt hoặc 5 mắt dò dòng của xe Arduino), thuật toán tốt nhất và nhẹ nhất là Lấy mẫu màu Pixel (Pixel Color Sampling) tại các vị trí mắt đọc dựa trên tọa độ của robot.
Dưới đây là nguyên lý toán học để xác định vị trí mắt đọc và đoạn mã JavaScript triển khai chi tiết.
1. Nguyên lý hình học: Xác định vị trí mắt đọc (Sensor Position)
Thanh cảm biến thường được gắn ở phía trước gầm xe. Giả sử bạn có 3 mắt đọc: Trái (Left), Giữa (Center), Phải (Right).
Các mắt đọc này di chuyển và xoay theo thân xe. Do đó, bạn cần dùng công thức lượng giác để tính tọa độ \((x_s, y_s)\) của từng mắt đọc dựa trên:
  • Tâm robot \((x, y)\) và góc quay hiện tại \(\theta \).
  • Khoảng cách từ tâm robot ra phía trước (độ dài mũi xe \(d\)).
  • Khoảng cách lệch sang hai bên của mắt Trái/Phải (độ rộng thanh cảm biến \(w\)).
Đối với mắt Giữa, \(w = 0\). Đối với mắt Trái, \(w = -\text{offset}\). Đối với mắt Phải, \(w = +\text{offset}\).
2. Triển khai bằng JavaScript
Thuật toán này sẽ sử dụng đối tượng CanvasRenderingContext2D của HTML5 Canvas để đọc dữ liệu màu sắc (RGBA) của sàn đấu tại đúng tọa độ mắt đọc.
javascript
class LineSensorSystem {
    constructor(offsetFromCenter = 15, forwardDistance = 30) {
        this.forwardDistance = forwardDistance; // Khoảng cách từ tâm robot ra phía trước (d)
        this.offset = offsetFromCenter;         // Khoảng cách từ mắt giữa sang mắt trái/phải (w)
        
        // Trạng thái của 3 mắt đọc (0: Nền trắng, 1: Vạch đen)
        this.states = { left: 0, center: 0, right: 0 };
        
        // Lưu tọa độ thực tế của các mắt để vẽ lên UI (tùy chọn)
        this.positions = { left: {x:0, y:0}, center: {x:0, y:0}, right: {x:0, y:0} };
    }

    /**
     * Cập nhật trạng thái đọc vạch của cảm biến
     * @param {Object} robot - Đối tượng robot chứa (x, y, angle)
     * @param {CanvasRenderingContext2D} ctx - Context của Canvas chứa bản đồ vạch đường
     */
    update(robot, ctx) {
        const cos = Math.cos(robot.angle);
        const sin = Math.sin(robot.angle);

        // 1. Tính toán tọa độ (x, y) của 3 mắt đọc trên màn hình
        // Mắt Giữa (Center)
        this.positions.center.x = robot.x + this.forwardDistance * cos;
        this.positions.center.y = robot.y + this.forwardDistance * sin;

        // Mắt Trái (Left) - Lệch một khoảng (-offset) theo trục vuông góc với hướng xe
        this.positions.left.x = robot.x + this.forwardDistance * cos - this.offset * sin;
        this.positions.left.y = robot.y + this.forwardDistance * sin + this.offset * cos;

        // Mắt Phải (Right) - Lệch một khoảng (+offset)
        this.positions.right.x = robot.x + this.forwardDistance * cos + this.offset * sin;
        this.positions.right.y = robot.y + this.forwardDistance * sin - this.offset * cos;

        // 2. Quét màu pixel tại các tọa độ đó và chuyển sang hệ Nhị phân (0 hoặc 1)
        this.states.left = this.isPixelBlack(ctx, this.positions.left.x, this.positions.left.y);
        this.states.center = this.isPixelBlack(ctx, this.positions.center.x, this.positions.center.y);
        this.states.right = this.isPixelBlack(ctx, this.positions.right.x, this.positions.right.y);

        return this.states;
    }

    /**
     * Hàm kiểm tra xem pixel tại tọa độ (x, y) có phải là màu đen (vạch đường) hay không
     */
    isPixelBlack(ctx, x, y) {
        // Đảm bảo tọa độ nằm trong phạm vi canvas để tránh crash
        if (x < 0 || x >= ctx.canvas.width || y < 0 || y >= ctx.canvas.height) return 0;

        // Lấy dữ liệu RGBA của 1 pixel tại tọa độ (x, y)
        // Hàm này trả về mảng [R, G, B, A] từ 0-255
        const pixel = ctx.getImageData(Math.floor(x), Math.floor(y), 1, 1).data;
        
        const r = pixel[0];
        const g = pixel[1];
        const b = pixel[2];

        // Ngưỡng (Threshold) để xác định màu tối/đen. 
        // Nếu trung bình cộng của R, G, B < 100 thì coi như đang đè lên vạch đen
        const brightness = (r + g + b) / 3;
        return brightness < 100 ? 1 : 0;
    }
}
Use code with caution.
3. Cách tích hợp vào bài học Lập trình của trẻ
Khi trẻ viết code cho bài học "Xe dò đường tự động", hệ thống sẽ cung cấp cho trẻ giá trị của 3 mắt đọc này. Trẻ sẽ sử dụng cấu trúc Nếu... Thì... để điều khiển tốc độ 2 bánh xe dựa trên logic nhị phân thực tế ngoài đời:
  • [0, 1, 0] (Mắt giữa chạm vạch đen, 2 mắt bên ngoài nền trắng): Xe đang đi thẳng đẹp \(\rightarrow \) setMotors(80, 80) (Hai bánh chạy đều).
  • [1, 0, 0] (Mắt trái chạm vạch, xe bị lệch sang phải): Cần cua gấp sang trái \(\rightarrow \) setMotors(20, 80) (Bánh phải chạy nhanh hơn để đẩy xe vẹo sang trái).
  • [0, 0, 1] (Mắt phải chạm vạch, xe bị lệch sang trái): Cần cua gấp sang phải \(\rightarrow \) setMotors(80, 20).
  • [0, 0, 0] (Mất vạch hoàn toàn): Xoay tại chỗ để tìm lại vạch hoặc dừng lại.
💡 Mẹo tối ưu hiệu năng (Performance) cho Web App
Hàm ctx.getImageData tiêu tốn khá nhiều tài nguyên CPU nếu gọi liên tục nhiều lần trong mỗi frame. Để web app chạy mượt 60 FPS:
  1. Bạn nên tạo một Canvas phụ (Offscreen Canvas) kích thước nhỏ, chỉ vẽ riêng đường line màu đen để quét màu, tránh việc quét trúng các chi tiết trang trí khác của map.
  2. Hoặc thay vì quét pixel hình ảnh, bạn có thể định nghĩa đường đi là các đoạn thẳng toán học (Vector Lines) và dùng thuật toán tính khoảng cách từ điểm (mắt đọc) đến đoạn thẳng đó. Nếu khoảng cách < độ rộng vạch, coi như bằng 1. Cách này chạy mượt hơn rất nhiều so với quét pixel truyền thống.
